# Deco&Mat Stationers — Full Website Package (Client Site + Admin Panel + Mobile API)

This is your **complete backend**: the customer-facing website (`client/`),
the admin dashboard (`admin/`) where you manage products/categories/orders,
the shared assets, the database, and the `api/` folder the Flutter app talks
to. Upload this whole folder to your hosting — nothing else is needed.

## 1. Upload

Upload every folder here (`admin/`, `api/`, `assets/`, `client/`,
`includes/`, `database/`, `index.php`) into your hosting account's
`public_html/` (or a subfolder, e.g. `public_html/stationery/` if you want
the site at `yourdomain.com/stationery`).

## 2. Create the database

In cPanel → **MySQL Databases**: create a database (e.g. `yourcpaneluser_stationery`)
and a database user with all privileges on it.

In cPanel → **phpMyAdmin**, select that database, then **Import**:

**Choose ONE of these two starting points:**

- **`database/clean_export.sql`** — this is your **real, existing data**:
  it already has actual products/categories you'd set up, at least one
  real customer, and real orders placed on the old site. Use this if you
  want to keep everything as it already was.
- **`database/stationery.sql`** — a smaller **demo/sample dataset**. Use
  this only if you want to start fresh instead.

Then, either way, also import:
- `api/security_additions.sql` (adds login-attempt rate limiting — safe
  to run on top of either option above)

⚠️ If you import `clean_export.sql`, note the admin login it contains is
`station` (not a real email format, but that's the value stored) with
whatever password you originally set — I don't have that password since
it's stored as a bcrypt hash. If you don't remember it, open
phpMyAdmin → `admins` table → edit that row → set the `password` column
to a new hash generated by running this once anywhere with PHP:
`<?php echo password_hash('yournewpassword', PASSWORD_DEFAULT); ?>`

## 3. Set your database credentials — in BOTH of these files

They must match each other and match what you created in step 2.

**`includes/db.php`** (powers the client website + admin panel):
```php
$host = 'localhost';
$dbname = 'yourcpaneluser_stationery';
$username = 'yourcpaneluser_dbuser';
$password = 'your-db-password';
```

**`api/bootstrap.php`** (powers the mobile app):
```php
$host = 'localhost';
$dbname = 'yourcpaneluser_stationery';
$username = 'yourcpaneluser_dbuser';
$password = 'your-db-password';
```
Also in `api/bootstrap.php`, set:
- `API_SECRET` → change to a long random string (this signs mobile app login tokens)
- `SITE_BASE_URL` → your real domain, e.g. `https://decomatstationers.com/stationery`
  (used to build image URLs the app displays)

## 4. Turn on HTTPS

cPanel → **SSL/TLS Status** → enable AutoSSL for your domain. Confirm the
site loads on `https://` before connecting the mobile app to it — Play
Store requires this.

## 5. Folder permissions

Make sure these folders are writable by PHP (cPanel File Manager → right
click → Permissions → 755, or 775 if 755 doesn't work on your host):
```
assets/images/products/
assets/images/categories/
assets/images/payments/
```
Products, category images, and mobile-app checkout payment screenshots are
all uploaded into these.

## 6. Log into the admin dashboard

Visit `https://yourdomain.com/stationery/admin/login.php` (adjust path to
where you uploaded it).

- If you imported **`stationery.sql`** (sample data): default seeded
  login is `admin@stationery.com` / `1234`. **Change this password
  immediately after logging in** — it's a known default anyone could look up.
- If you imported **`clean_export.sql`** (your real data): log in with
  your existing admin login (`station` + your original password — see
  the note in step 2 if you've forgotten it).

From the admin dashboard you can:
- **Products** → add/edit/delete, set category, price, stock, upload image
- **Categories** → add/edit/delete
- **Orders** → view all orders placed (including ones from the mobile app),
  mark pending/completed
- **Customers** → view registered customers (mobile app + website)
- **Reports** → sales reports

The mobile app and the website both read/write the exact same database —
anything you add in the admin panel shows up in the app immediately, and
any order placed in the app shows up in the admin panel's Orders section.

## 7. Point the Flutter app at this live site

In `flutter_app/lib/config.dart`:
```dart
static const String apiBaseUrl = 'https://yourdomain.com/stationery/api';
```
Rebuild the app (`flutter run` for testing, `flutter build appbundle
--release` when ready for the Play Store).

## 8. Privacy Policy page (required for Play Store)

`privacy-policy.html` is included at the root of this package — once
uploaded, it will be live at e.g. `https://yourdomain.com/stationery/privacy-policy.html`.
It already contains real policy text (not a placeholder) covering what
data is collected, how it's used, security measures, and how to request
deletion.

Before you use it:
- Update the contact email inside it if `support@decomatstationers.com`
  isn't the address you actually want to use.
- Put its final live URL into `flutter_app/lib/config.dart` →
  `privacyPolicyUrl`, and into Play Console's store listing (Privacy
  Policy field) and Data Safety section.

## 9. New features added

**Welcome email on signup** — works via PHP's `mail()` out of the box on
most cPanel hosting (see `includes/mailer.php` for SMTP upgrade
instructions if emails don't arrive/land in spam).

**Order via WhatsApp** — every product (shop grid, homepage, product
detail page) has a green WhatsApp button that opens a chat to
**0772616006** with the product name and price pre-filled. Number is set
in `includes/functions.php` → `WHATSAPP_ORDER_NUMBER`.

**Get the App / install on phones**:
- A "Get the Deco&Mat Stationers App" banner is on the homepage, linking
  to `PLAY_STORE_URL` and `APK_DOWNLOAD_URL` (both in
  `includes/functions.php` — update `PLAY_STORE_URL` once your Play
  Store listing is live; drop a built `.apk` into
  `assets/downloads/decomat-stationers.apk` for the direct-download link
  to work in the meantime).
- The site itself is now a basic **PWA** (`manifest.json` +
  `service-worker.js`) — once served over HTTPS, phone browsers will
  offer "Add to Home Screen" / "Install app", giving customers an
  app-like icon and experience immediately, even before the Play Store
  listing is approved.

## What's in this package

```

includes/            # shared PHP (db connection, helper functions)
assets/              # images, CSS, JS
database/            # clean_export.sql (your real data) OR stationery.sql (demo data) - import ONE of these first
api/                 # JSON REST API - what the Flutter mobile app calls
  ├── security_additions.sql  # import this second
  ├── README.md               # API endpoint reference
  └── bootstrap.php           # <- edit DB credentials + API_SECRET here
```
